# Ideation & Roadmap Plugin — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Claude Code plugin with `/ideation` and `/roadmap` skills that dispatch parallel subagents for deep project analysis, generate interactive HTML reports, and support GitHub issue lifecycle management.

**Architecture:** Plugin follows bvdr marketplace convention (`.claude-plugin/plugin.json` + `commands/`). Orchestrator skills in `commands/` dispatch subagents using Agent tool with prompts from `agents/`. HTML reports generated from static templates in `assets/` with JSON data injection. All output written to `.claude/ideation/` and `.claude/roadmap/` in the target project.

**Tech Stack:** Claude Code plugin system, Agent tool for subagent dispatch, `gh` CLI for GitHub integration, HTML/CSS/JS for reports, Auto-Claude prompt adaptations.

## Conventions

**File creation:** All file paths in tasks are relative to the plugin directory (`plugins/bvdr-ideation-and-roadmap/`). Use Write tool with absolute paths.

**Git commands:** All `git add` and `git commit` commands must use paths relative to the **repo root** (`/Users/bogdand/gits/bvdr/claude-plugins/`). Every git path in this plan uses the `plugins/bvdr-ideation-and-roadmap/` prefix.

**Plugin install path at runtime:** The orchestrator skills (`commands/ideation.md` and `commands/roadmap.md`) cannot know their own install path at runtime. The workaround: the orchestrator instructs the LLM to use `Glob` to find the plugin's agent files by searching for the plugin name pattern. For example:
```
Find the git-analysis agent prompt by running: Glob("**/bvdr-ideation-and-roadmap/agents/context/git-analysis.md")
```
This pattern is reliable because the plugin name is unique. The orchestrator prompt should include this discovery mechanism at the top.

**Atomic writes:** When the orchestrator merges JSON files, it writes to `filename.tmp.json` first, validates the JSON, then renames to `filename.json`:
```bash
mv .claude/ideation/deep-analysis.tmp.json .claude/ideation/deep-analysis.json
```

**Schema versioning:** ALL generated JSON files must include `"schema_version": "1.0"` as a top-level field. The orchestrator checks this before using cached files.

**`--only` alias mapping:**
| Alias | Full slug |
|-------|-----------|
| `ci` | `code-improvements` |
| `cq` | `code-quality` |
| `doc` | `documentation` |
| `sec` | `security` |
| `perf` | `performance` |
| `ux` | `ui-ux` |

**Readme.txt template** (used in both `.claude/ideation/` and `.claude/roadmap/`):
```
This folder contains analysis output generated by the bvdr-ideation-and-roadmap
Claude Code plugin (https://github.com/bvdr/claude-plugins).

These files are generated artifacts and are git-ignored by default.
To regenerate, run /ideation or /roadmap in Claude Code.
```

## Task 2: Deep Analysis — Git Analysis Agent

**Files:**
- Create: `agents/context/git-analysis.md`

**Reference:** Auto-Claude has no equivalent — this is new. Spec Section 5 defines the data sources and output schema.

- [ ] **Step 1: Write the git-analysis agent prompt**

This agent is dispatched by the orchestrator. It must:
1. Analyze last 500 commits via `git log --oneline -500` and `git log --name-only -500`
2. Query merged PRs (last year) via `gh pr list --state merged --limit 500 --json number,title,mergedAt,body`
3. Query open PRs via `gh pr list --state open --json number,title,author,body`
4. Query closed-not-merged PRs via `gh pr list --state closed --json number,title,closedAt,body` and filter
5. Query open issues via `gh issue list --state open --json number,title,labels,milestone,body --limit 200`
6. Analyze branch activity via `git branch -a --sort=-committerdate`
7. Calculate file churn (hot spots) from commit history
8. Calculate cold spots (directories with no recent commits)
9. Write output to `{output_dir}/git-analysis.json`

The prompt must include:
- `## CONTEXT FILES` section with placeholder for output directory path
- Clear instructions to handle missing `gh` CLI gracefully
- Clear instructions to handle non-git-repos gracefully
- Output JSON schema matching the `git_activity`, `open_issues`, and `direction` sections of `deep-analysis.json` from spec

## Task 9: Ideation Orchestrator Skill

**Files:**
- Create: `commands/ideation.md`

**Reference:** Spec Sections 3 and 6. Night-shift orchestrator at `plugins/bvdr-nightshift/commands/night-shift.md` as convention reference.

- [ ] **Step 1: Write the ideation orchestrator**

This is the main `/ideation` skill. It must handle all subcommands:

**Argument parsing** (from skill args):
- No args or `run` → full ideation run
- `--only type1,type2` → filter types (accept full slugs and short aliases: ci, cq, doc, sec, perf, ux)
- `--refresh` → force re-run deep analysis
- `--no-open` → don't auto-open HTML report
- `help` → print help text (from spec Section 11)
- `accept id1 id2 ...` → mark ideas as accepted
- `dismiss id [--reason "..."]` → mark idea as dismissed
- `status` → print review summary
- `create-issues` → batch create GH issues for accepted ideas
- `create-issue id` → create single GH issue

**Run flow** (default command):

Phase 0: Setup
- Detect project root (`git rev-parse --show-toplevel || pwd`)
- Create output dir (`.claude/ideation/`)
- Write `.gitignore` and `Readme.txt` if not present
- Check for cached `deep-analysis.json` (< 24h old, correct `schema_version`)

Phase 1: Deep Analysis (if not cached or `--refresh`)
- Read `agents/context/git-analysis.md` from plugin install path
- Compose prompt with output_dir path
- Dispatch git-analysis subagent (Agent tool, `run_in_background: false`)
- Read `agents/context/codebase-scan.md`, compose, dispatch (sequential, `run_in_background: false`)
- Read `agents/context/competitive-research.md`, compose, dispatch (sequential, `run_in_background: false`)
- Merge `git-analysis.json` + `codebase-scan.json` + `competitive-research.json` → `deep-analysis.json` (atomic write via tmp file)
- Add `schema_version: "1.0"` and `created_at` timestamp

Phase 2: Ideation (parallel)
- Determine which types to run (all 6 or `--only` subset)
- For each type: read agent prompt from `agents/ideation/{type}.md`, compose with `deep-analysis.json` path
- Dispatch all agents in parallel (single message with multiple Agent tool calls, `run_in_background: true`)
- Wait for all to complete

Phase 3: Merge & Report
- Read all `{type}.json` output files
- If existing `ideation.json` exists: preserve accepted/dismissed/created items, remove old pending items
- Merge new ideas as `status: "pending"`
- If new idea matches previously dismissed (same title + type) → auto-dismiss
- Write `ideation.json` with summary stats
- Read `assets/ideation-report-template.html` from plugin install path
- Replace `{{IDEATION_DATA}}` with JSON data
- Write `report.html`
- Unless `--no-open`: run `open report.html`
- Print terminal summary

**Accept/Dismiss/Status/Create-Issues subcommands:**
- Read `ideation.json`
- Update status fields
- For create-issues: check `issues-tracker.json` for duplicates, use `gh issue create` with formatted body per spec Section 9, apply labels, update tracker
- After any change: regenerate `report.html`

- Merge preserves reviewed items
