# Roadmap Orchestrator

You are the orchestrator for the Roadmap system. You run autonomously and handle all subcommands. Read this entire file before taking any action.

---

## Step 0: Parse Arguments

Read the skill args string and determine the subcommand and flags.

**Subcommand detection** (first non-flag token):

| Args | Subcommand |
|------|-----------|
| (empty or no non-flag tokens) | `run` |
| `help` | `help` |
| `accept <id> [<id>...]` | `accept` |

| `status` | `status` |

Once you know the subcommand, jump to that section below.

## Subcommand: `run` (default)

### Phase 0: Setup

**Detect project root:**
```bash
git rev-parse --show-toplevel 2>/dev/null || pwd
```
Store as `PROJECT_ROOT`.

**Detect project name:**
```bash
basename "$(git rev-parse --show-toplevel 2>/dev/null || pwd)"
```
Store as `PROJECT_NAME`.

**Set output directory:**
```
OUTPUT_DIR = {PROJECT_ROOT}/.claude/roadmap
```

**Create output directory:**
```bash
mkdir -p "{OUTPUT_DIR}"
```

**Write `.gitignore`** to `{OUTPUT_DIR}/.gitignore` if it does not already exist:
```
# Generated by bvdr-ideation-and-roadmap plugin
*
!.gitignore
!Readme.txt
```

**Write `Readme.txt`** to `{OUTPUT_DIR}/Readme.txt` if it does not already exist:
```
This folder contains analysis output generated by the bvdr-ideation-and-roadmap
Claude Code plugin (https://github.com/bvdr/claude-plugins).

These files are generated artifacts and are git-ignored by default.
To regenerate, run /ideation or /roadmap in Claude Code.
```

**Check deep-analysis cache:**

Check two locations in order:

1. First check `{PROJECT_ROOT}/.claude/ideation/deep-analysis.json` (cross-skill cache)
2. Then check `{OUTPUT_DIR}/deep-analysis.json`

Use the first file found if ALL of the following are true:
1. File exists and contains valid JSON
2. `schema_version` field equals `"1.0"`
3. `created_at` field is less than 24 hours ago (compare to current time via `date -u +%s`)
4. `FORCE_REFRESH` flag is NOT set

If the cache is valid, log: `"Using cached deep analysis from {created_at} ({source})"` (where `{source}` is either `ideation` or `roadmap`) and skip to Phase 2.

Set `DEEP_ANALYSIS_PATH` to the path of the file that will be used (cache or newly generated).

**Verify and merge with existing `roadmap.json`:**

After the agent completes, read the newly generated `{OUTPUT_DIR}/roadmap.json`. If missing, print `"Error: Features agent did not produce roadmap.json. Check agent output for errors."` and stop.

Check if a previous `roadmap.json` existed before this run (you should have noted this in Phase 0). If a previous version exists:

1. Load the previous file's `features` array.
2. Collect all features whose `status` is not `"pending"` (i.e., keep `"accepted"`, `"dismissed"`, `"created"` items). These are `preserved_features`.
3. For each new feature in the freshly generated file:
   - Set `status: "pending"` (the agent should have done this, but enforce it here)
   - Check if any preserved feature has the same `title` AND `status: "dismissed"`. If so, auto-dismiss the new feature: set `status: "dismissed"`, `dismissed_reason: "previously dismissed"`, `reviewed_at: <current ISO timestamp>`.
4. Merge: `final_features = preserved_features + new_features` (deduplicated by `id`)
5. Write the merged features back to `roadmap.json`.

If no previous `roadmap.json` existed, the features agent output is used as-is.

## Subcommand: `accept`

**Args format:** `accept id1 [id2 id3 ...]`

Parse all IDs after the `accept` token.

1. Read `{OUTPUT_DIR}/roadmap.json` — if missing, print `"No roadmap data found at .claude/roadmap/roadmap.json. Run /roadmap first."` and stop.
2. Get current ISO timestamp: `date -u +"%Y-%m-%dT%H:%M:%SZ"`
3. For each provided ID:
   - Find the feature in `features` array where `id` matches
   - If found: set `status: "accepted"`, `reviewed_at: <timestamp>`
   - If not found: log `"Warning: ID {id} not found"`
4. Write updated `roadmap.json`
5. Regenerate `report.html` (same process as Phase 4 above)
6. Print: `"Accepted: {id1}, {id2}, ..."`

## Subcommand: `create-issues`

1. Read `{OUTPUT_DIR}/roadmap.json` — if missing, print error and stop.
2. Read `{OUTPUT_DIR}/issues-tracker.json` — if missing, initialize as `{}`.
3. Collect all features with `status: "accepted"`.
4. If none, print: `"No accepted features to create issues for. Use /roadmap accept <id> first."` and stop.
5. Get current ISO timestamp.

For each accepted feature (in order):

**a. Check if already created:**
If the feature's `id` already exists as a key in `issues-tracker.json`, log: `"Skipping {id} — issue already created: #{number}"` and skip.

**b. Resolve phase name:**
Look up the feature's `phase_id` in `roadmap.json` `phases` array to get the phase name.

**c. Create GH issue:**

Build the body:
```markdown
## {title}

{description}

### Rationale
{rationale}

### Acceptance Criteria
- {criterion 1}
- {criterion 2}

### User Stories
- {story 1}
- {story 2}

### Complexity: {complexity} | Impact: {impact} | Priority: {priority}

### Dependencies
{for each dep_id in dependencies: - feature-{dep_id}: {title of that feature}}
{if dependencies is empty: _None_}

### Related Issues
{for each item in related_issues: - #{number} — {relationship}: {title}}
{if related_issues is empty: _None_}

---
*Generated by [bvdr-ideation-and-roadmap](https://github.com/bvdr/claude-plugins) plugin*
*Source: roadmap — {id} (Phase: {phase_name})*
```

Map priority to label:
- `must` → `must-have`
- `should` → `should-have`
- `could` → `could-have`
- `wont` → `wont-have`

Run:
```bash
gh issue create \
  --title "{title}" \
  --body "{body}" \
  --label "roadmap-generated,{priority_label}"
```

If the label doesn't exist, `gh` will create it. If `gh` returns an error, log the error, mark the feature as `"gh_error": "<error message>"`, and continue to the next feature.

**d. Update state after successful creation:**
- Parse the returned URL to extract the issue number
- Set `feature.status = "created"`, `feature.gh_issue = { "number": <n>, "url": "<url>" }`, `feature.created_issue_at = <timestamp>`
- Add to tracker: `issues-tracker[feature.id] = { "feature_id": feature.id, "gh_issue_number": <n>, "gh_issue_url": "<url>", "created_at": <timestamp> }`

6. Write updated `roadmap.json`
7. Write updated `issues-tracker.json`
8. Regenerate `report.html`

9. Print summary:
```
=== ISSUES CREATED ===

Created:
  [{id}] {title} → #{number} {url}
  ...

Skipped (already created):
  [{id}] {title} → #{number}
  ...

Failed:
  [{id}] {title} → {error}
  ...
```

## Error Handling Rules

These rules apply throughout all subcommands:

1. **`roadmap.json` missing**: For `accept`, `dismiss`, `status`, `create-issues`, `create-issue` — print `"No roadmap data found at .claude/roadmap/roadmap.json. Run /roadmap first."` and stop.
2. **Agent file not found**: Log warning and stop — roadmap generation cannot proceed without agent files.
3. **Discovery agent produces no output file**: Print error and stop. The features phase depends on discovery.
4. **Features agent produces no output file**: Print error and stop.
5. **JSON parse error on any agent output**: Log warning for that file. For deep-analysis component files (git-analysis, codebase-scan, competitive-research), skip that file and merge with what's available. For roadmap.json or roadmap_discovery.json, stop with an error.
6. **`deep-analysis.json` write fails**: Log error and continue to Phase 2 with whatever partial data was gathered.
7. **`gh` not available**: For `create-issues`/`create-issue` — print `"Error: gh CLI not available or not authenticated. Run 'gh auth login' first."` and stop.
8. **`report.html` template not found**: Skip HTML report, log warning. Terminal output is always produced regardless.
9. **`open` command fails (non-macOS)**: Silently ignore. Report path is printed in terminal summary.
10. **ID not found in `accept`/`dismiss`**: Log warning and skip that ID. Continue processing remaining IDs.
11. **`--skip-discovery` with no existing `roadmap_discovery.json`**: Print `"Error: No existing discovery.json found. Run /roadmap first without --skip-discovery."` and stop.
